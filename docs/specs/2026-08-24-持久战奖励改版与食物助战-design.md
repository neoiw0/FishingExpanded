# 设计规格：持久战奖励降档限次 + 助战附加食物助战（暂定 BATCH-084）

- 状态：**待用户审阅**（批准前不实施任何代码修改）
- 日期：2026-08-24
- 决策来源：用户 2026-08-24 会话确认（方案方向、p=1/2、范围 A、奖励池、小游戏开始时发放、补差 buff 规则）
- 关联背景：堵住"刻意拖满 60 秒故意失败刷海泡布丁"的利用路径

## 1. 目标与非目标

**目标**
1. 持久战失败安慰奖降档（+4/+3 料理 → +2/+1 食物）并加每日频次上限，使"拖时间故意失败"无利可图。
2. 海泡布丁改为经"食物助战"渠道限量发放：与真实钓鱼行为绑定（当天必须下竿）、每周硬上限 2 个、不可囤积、不可读档重抽。
3. 不影响现有皇冠助战的概率、逻辑与手感。

**非目标**
- 不改动失败/成功结算、难度等级、经验、数量、品质等其他系统。
- 不新增 GMCM 配置项（所有数值为常量；如后续需要再议）。
- 不处理挑战鱼饵增产、力竭等既有机制的数值。

## 3. REQ-A：持久战失败奖励改版

### 3.1 规则
- 触发边界不变：`FailureRecorded` 单发分支内的 `TryGrantPerseveranceReward`。
- **30 秒 ≤ 战斗 < 60 秒**：50% 概率从 30 秒档池三选一（均匀随机）；**每天最多发 1 次**。
- **战斗 ≥ 60 秒**：60% 概率从 60 秒档池二选一（各 50%）；**每天最多发 1 次**。
- 两档计数**相互独立**（同一天理论最多 1 份 +1 食物 + 1 份 +2 食物）。
- 当日该档已达上限：直接跳过（不掷骰、不发物品、不弹提示），其余失败逻辑照常。
- ≥60 秒档不参与 30 秒档抽奖的不叠加规则维持不变。
- 概率维持 50%/60% 不变。
- **海泡布丁与 +3 料理永久退出本渠道**。
- 补差 buff 不适用于本渠道（用户选定范围 A）。

### 3.2 计数实现
- 内存态、零存档字段：`DifficultyManager` 内按玩家（`UniqueMultiplayerID`）记两档当日已发次数，`DayStarted` 统一重置（复用 BATCH-061 `ResetDailyHarvest` 同款模式）。
- 测试命令 `fish_persisttest <30|60>` 强制路径**绕过**每日上限且不计入正常计数，日志带「测试强制」标记（保证验收可重复，且不污染生产计数）。

## 4. REQ-B：助战附加"食物助战"

### 4.1 每日掷骰
- `DayStarted` 时每玩家掷一次：命中概率 `p = (可计数皇冠数 ÷ 61) × 0.5`。
  - 0 皇冠恒不命中；61 皇冠 p=0.5，实际期望 ≈1.8 次/周 ≈ 每 3.9 天一个（受周上限截断，用户已确认接受）。
- **掷骰结果（命中与否）当日写入玩家存档**，读档回滚不得重掷（防 save-scum 刷骰）。

### 4.2 周窗口与上限
- 每周最多 2 个：窗口 1 = 周一~周三（上限 1），窗口 2 = 周四~周日（周四进日时重置计数，上限 1）。
- 窗口内额度已用尽时：当日即使掷中也不发放（掷骰照常、结果照常入档，作废）；推荐实现为掷骰前先查额度，额度尽则直接记"未中"，行为等价、状态更少。
- 下周一自动进入新窗口（清零），无需额外存储周期标识（由游戏日历推算）。

### 4.3 消费与发放（小游戏开始边界）
- 当日命中且窗口有额度时：当天**第一个符合条件的** `BobberBar` 构造边界消费命中——
  - 符合条件 = 非鱼王 且 未使用挑战鱼饵（两者均豁免原助战，口径一致）；
  - 顺延规则：首个小游戏不符合条件则**不消耗**，顺延至当天下一个符合条件的实例；全天无条件符合则作废（次日重新掷骰）。
- 发放内容（一次性）：
  - 物品：70% 从 {(O)242, (O)728, (O)730} 均匀三选一；30% 海泡布丁 `(O)265`；
  - 经 `owner.addItemByMenuIfNecessary` 入包，背包满走原生溢出菜单；
  - **补差 buff（范围 A，仅本渠道）**：设奖励档位 r（3 或 4），玩家当前**食物类钓鱼 buff** 为 b：
    - `b < r`：按所发食物的原生钓鱼 buff 效果与时长（见 §2 表）给玩家应用钓鱼 +r buff；
    - `b ≥ r`（含相等）：只给物品，不应用 buff，不顶掉玩家既有食物 buff；
    - 补差只含钓鱼等级分量，不复刻龙虾浓汤的体力上限+50（有意取舍，用户可改）；
    - 应用使用 `food` 类别，使 §7.6.1"小游戏期间食物 buff 不走时"机制自然生效。
- **执行顺序**：构造边界内先完成物品发放与 buff 应用，之后才让原生构造读取钓鱼等级计算绿条高度——确保本场战斗直接吃到加成。
- 与原助战关系：命中实例强制 100% 走原助战展示流程（选鱼权重、临时等级、15 秒助战文案全照旧）；其余实例的原助战概率逻辑不受任何影响。

### 4.4 存储与所有权
- 新增存档字段挂在 `FishDifficultyData`（`Farmer.modData`，按玩家隔离；键名实施时定）：
  - 当日掷骰结果（已掷+命中与否，进日重置）；
  - 当前窗口已用量（窗口切换时清零）。
- `DifficultyManager` 为唯一写入者；`BobberBarPatches` 只请求操作，不直接读写上述键。
- 旧存档缺键默认视为"未掷 / 0 用量"。
- 内存态无需新增：REQ-A 计数见 §3.2。

## 5. 边界情况矩阵

| 场景 | 行为 |
|---|---|
| 鱼王小游戏 | 不消费命中，顺延（原助战豁免口径一致） |
| 挑战鱼饵小游戏 | 不消费命中，顺延（§7.5 无助战口径一致） |
| 节日原生模式（开关关） | 节日内小游戏不介入、不消费；命中顺延至节后普通小游戏 |
| 夜市潜艇钓鱼 | 不走 `BobberBar` 链，天然不消费 |
| 背包满 | 物品走原生溢出菜单；buff 应用不受背包影响 |
| 中途退出小游戏 | 原版小游戏无主动中止路径；命中即消费、物品不回收、窗口用量不因本场失败而回退 |
| 读档回滚 | 当日掷骰结果与窗口用量随存档还原，不重掷 |
| 多人在线/分屏 | 各玩家独立掷骰、独立窗口计数、各自发放与 buff |
| 返回标题/换存档 | 内存态随重载重建；存档态随档隔离 |
| 与每日收获限额（333） | 无交互（不同所有者、不同资源） |

## 12. 实施细化记录（2026-08-24 实施，BATCH-084）

1. 补差 buff 采用所发食物的**完整原生食物 buff 组**（`Object.GetFoodOrDrinkBuffs()` + `Farmer.applyBuff`），即包含龙虾浓汤的体力上限 +50——对 §4.3"仅钓鱼分量"保守假设的实现细化，依据用户原话"对应buff…持续时间按照食物的"取原生保真。
2. 物品入包延后至首个 update Tick：构造边界直接入包会在背包满时与原生菜单赋值竞争；延后后与本模组持久战奖励既定发放路径同语义。补差 buff 仍在构造边界应用。
3. 候选 DLL SHA256 `D18CC8C06E6959B6C9EC0DA22CE419CA45100516315F6895245E88EC5478F1E9`（0 警告 0 错误；静态验证后修订）；部署与集中测试待用户授权。
4. 静态验证（2026-08-24）：①原生契约证实——`BobberBar` 构造 L153 `bobberBarHeight = 96 + Game1.player.FishingLevel * 8`，且 `Farmer.FishingLevel => fishingLevel.Value + buffs.FishingLevel` 含食物 buff → 补差 buff 在构造 Prefix 应用确使本场绿条受益；②修复待发槽泄漏路径（原生构造异常时 Postfix 不执行 → Prefix 开头先清空 `_pendingFoodAssist`）；③物品入包实际位于 Update_Postfix 随机源恢复之后——不消耗挑战鱼饵背板固定种子序列（优于原计划的 Update_Prefix 位置，注释已改准确）。
5. **设计修订 BATCH-084A（2026-08-24 部署后用户指令，方案 A）**：食物助战与皇冠助战**互斥**——命中实例改为"纯食物助战"（只发物品+补差 buff+食物文案 15 秒），不触发皇冠助战；其余实例原助战概率照常。§4.3"命中实例 100% 助战展示"条款由本修订覆盖。版本升至 1.0.2 并随修订重新部署、重新打包发布包。
